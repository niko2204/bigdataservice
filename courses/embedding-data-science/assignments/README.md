# 임베딩 기반 데이터 과학 · 과제 운영 안내

이 디렉터리의 과제는 결과 화면을 제출하는 실습이 아니라, **명세를 해석하고 재현 가능한
실험으로 주장을 입증하는 컴퓨터과학 과제**다. 학생은 모델 API를 호출하는 데서 끝나지
않고 데이터 계약, 기준선, 평가집합, 수학적 근거, 실패 사례와 시스템 한계를 설명해야 한다.

## 과제 구성

|과제|수행 형태|권장 시점|교과목 반영|핵심 산출물|
|---|---|---|---:|---|
|[과제 1](assignment01.md) · 희소/밀집 검색 비교|개인|5–7주차|10%|검색기 2종, qrels, 평가·오류 분석|
|[과제 2](assignment02.md) · 검색/RAG 파이프라인|개인|7–9주차|10%|청크 실험, 검색기 2종, 근거·거부 평가|
|[최종 프로젝트](final_project.md) · 임베딩 데이터 서비스|개인 또는 2–3인 팀|6–10주차|25%|제안서, 재현 가능한 시스템, 보고서, 시연|

마감 시각과 제출 플랫폼은 LMS 공지를 따른다. 과제 문서의 요구사항과 LMS 공지가 다르면
교수자가 마지막으로 공지한 내용을 우선한다.

## CMU형 과제 운영 원칙

이 과제는 공개된 CMU 컴퓨터과학·머신러닝 과제에서 보편적으로 사용하는 운영 구조를
참고해 다음 요소를 분명히 한다. 특정 과제의 문제나 정답을 복제한 것은 아니다.

1. **명세 우선**: 입력·출력 형식, 평가 단위, 금지된 지름길을 문서로 고정한다.
2. **코드와 서술의 결합**: 실행 결과뿐 아니라 수식, 설계 선택, 실패 원인을 평가한다.
3. **기준선 우선**: 최신 모델을 사용해도 단순한 기준선보다 나은지 같은 조건에서 증명한다.
4. **개발/평가 분리**: 모델 선택에 사용한 질의와 최종 성능 보고용 질의를 구분한다.
5. **공개 자기검사**: 제출 전 학생이 실행할 테스트와 체크리스트를 제공한다.
6. **개별 방어**: 제출 후 일부 파라미터나 코드를 바꾸고 결과 변화를 설명할 수 있어야 한다.

구조 설계 참고: [CMU 10-301/10-601 course components](https://www.cs.cmu.edu/~mgormley/courses/10601/),
[CMU 15-445 project specification example](https://15445.courses.cs.cmu.edu/spring2024/project2/).
본 강의의 데이터, 문제, 평가 지표와 제출물은 임베딩 기반 데이터 과학 수업에 맞게 독립적으로
작성했다.

## 공통 실행 환경 계약

- Python 3.10 이상, Google Colab 기본 런타임 또는 이에 준하는 환경을 사용한다.
- 모든 난수 생성기에 같은 `SEED`를 명시한다. 권장값은 `42`다.
- Notebook은 **런타임 다시 시작 → 전체 셀 실행**으로 오류 없이 끝나야 한다.
- 필수 경로는 상대경로로 작성하고 개인 컴퓨터의 절대경로를 사용하지 않는다.
- 모델명과 revision, 주요 라이브러리 버전, 실행일, CPU/GPU 종류를 기록한다.
- API 키, 토큰, 개인정보, 비공개 데이터 원문을 저장소나 Notebook 출력에 남기지 않는다.
- 대용량 모델이나 유료 API가 없어도 기준선과 평가 코드는 실행 가능해야 한다.

## 공통 제출 디렉터리

각 과제는 아래 구조를 기본으로 한다. 사용하지 않는 선택 파일은 생략할 수 있지만 필수
파일의 이름은 바꾸지 않는다. 과제 2처럼 `questions.csv`, `gold_evidence.csv`를 별도로
요구하는 경우에는 **개별 과제 문서의 제출물 명세가 이 공통 예시보다 우선**한다.

```text
student_id_assignmentXX/
├── README.md                 # 실행법, 환경, 파일 설명
├── assignmentXX.ipynb        # 위에서 아래로 실행 가능한 Notebook
├── requirements.txt          # 직접 추가한 패키지와 버전
├── data/
│   ├── documents.csv         # 분석 문서 또는 공개 데이터 참조표
│   ├── queries.csv           # 질의와 split
│   └── qrels.csv             # 질의-문서 관련성 정답
├── results/
│   ├── aggregate_metrics.csv # 실험 조건별 평균 지표
│   ├── per_query_metrics.csv # 질의별 지표
│   └── error_analysis.csv    # 실패 사례와 원인
├── report.pdf                # 과제별 지정 분량의 기술 보고서
└── AI_USAGE.md               # 생성형 AI 사용·검증 기록
```

Colab 링크만 제출하는 경우에도 위 CSV와 보고서를 Colab에서 다운로드할 수 있게 하고,
읽기 권한을 **링크가 있는 사용자**로 설정한다. 채점 시점에 접근할 수 없는 링크는 미제출로
처리될 수 있다.

## 공통 데이터 계약

문서 파일의 최소 스키마는 다음과 같다.

|열|형식|설명|
|---|---|---|
|`doc_id`|문자열, 고유|문서를 변하지 않게 식별하는 키|
|`title`|문자열|문서 제목|
|`text`|문자열, 비어 있지 않음|검색·분석 대상 본문|
|`source`|URL 또는 기관명|데이터 출처|
|`license`|문자열|라이선스 또는 이용 근거|
|`collected_at`|`YYYY-MM-DD`|수집·다운로드 날짜|

평가 정답 `qrels.csv`의 최소 스키마는 다음과 같다.

|열|형식|설명|
|---|---|---|
|`query_id`|문자열|질의 키|
|`doc_id` 또는 `chunk_id`|문자열|관련 문서/청크 키|
|`relevance`|정수 `0`, `1`, `2`|무관, 부분 관련, 직접 관련|
|`rationale`|문자열|왜 관련/무관한지 한 문장 근거|

## 허용되는 협업과 금지되는 협업

### 허용

- 강의노트, 공식 문서, 논문을 함께 읽고 개념을 토론한다.
- 일반적인 Python 오류와 라이브러리 사용법을 질문한다.
- 서로 다른 데이터로 얻은 실험 절차와 실패 유형을 비교한다.
- 출처를 밝히고 공개 코드의 아이디어를 참고한다.

### 금지

- 개인 과제의 Notebook, 정답 CSV, 보고서 문장을 공유하거나 복사한다.
- 다른 학생의 질의·qrels를 그대로 사용한다.
- 자신이 실행·검증하지 않은 생성형 AI 코드를 제출한다.
- 평가용 test 질의를 보고 모델, 프롬프트, 임계값을 반복 조정한다.
- 공개되지 않은 개인정보·저작물을 무단으로 수집해 제출한다.

## 생성형 AI 사용 규칙

생성형 AI 사용 자체는 감점 사유가 아니다. 다만 모든 사용은
[AI 사용 기록 템플릿](templates/AI_USAGE.md)에 남긴다.

- AI가 만든 코드는 셀 단위로 실행하고 입력·출력·예외 조건을 직접 검증한다.
- AI가 제안한 설명과 인용은 원 출처를 확인한다.
- 채택한 답변뿐 아니라 중요한 거부·수정 사례도 기록한다.
- 구술평가에서 코드 한 줄, 평가 지표 또는 파라미터를 변경했을 때 결과를 설명하지 못하면
  해당 구현·분석 영역은 점수를 받을 수 없다.

## 제출 전 공통 자기검사

```python
assert documents["doc_id"].is_unique
assert documents["text"].fillna("").str.strip().ne("").all()
assert set(qrels["relevance"].unique()) <= {0, 1, 2}
assert set(qrels["query_id"]) <= set(queries["query_id"])
assert set(qrels["doc_id"]) <= set(documents["doc_id"])
```

또한 다음을 사람이 직접 확인한다.

- [ ] 런타임을 초기화한 뒤 `Run all`이 성공한다.
- [ ] 보고서의 모든 수치가 제출 CSV에서 재계산된다.
- [ ] test split은 최종 평가 1회 외에 모델 선택에 사용하지 않았다.
- [ ] 성공 사례뿐 아니라 실패·편향·비용을 보고했다.
- [ ] 다른 사람이 10분 안에 실행법과 결과 파일 위치를 찾을 수 있다.
- [ ] 비밀정보와 개인정보가 출력·파일·Git 이력에 없다.

## 공통 감점·상한 규칙

세부 배점은 각 과제 문서를 따른다. 다음 문제는 여러 영역에 중복 감점하지 않고, 가장
적절한 영역에서 반영하거나 총점 상한을 적용한다.

|문제|원칙|
|---|---|
|Notebook이 처음부터 실행되지 않음|재현성 영역 0점, 실행 가능한 부분만 수동 평가|
|요구된 기준선 없음|총점 최대 70점|
|test 데이터로 모델·임계값 선택|평가 영역 0점, 총점 최대 70점|
|데이터 출처·이용 근거 없음|데이터 영역 0점, 필요 시 제출물 비공개 처리|
|API 키·개인정보 노출|즉시 비공개 요청 후 재현성·윤리 영역 0점|
|결과 조작 또는 타인 결과 복사|학칙과 교과목 학업윤리 절차 적용|
|구술에서 자신의 핵심 코드를 설명하지 못함|해당 구현 영역을 평가하지 않음|
