# 임베딩 기반 데이터 과학 · 과제 안내

이 과제들은 임베딩을 처음 배우는 학생도 순서대로 따라갈 수 있게 구성했다. 처음부터 완성된
서비스를 만들려고 하지 말고, **작은 데이터로 한 단계씩 실행한 뒤 규모를 늘린다.**

## 과제 한눈에 보기

|과제|권장 시간|최소 범위|핵심 결과|
|---|---:|---|---|
|[과제 1](assignment01.md)|6–8시간|문서 50개, 질의 10개, 검색기 2개|희소 검색과 임베딩 검색 비교|
|[과제 2](assignment02.md)|7–9시간|원문 10개, 질문 12개, 청크 조건 2개|근거를 찾고 없으면 응답 보류|
|[최종 프로젝트](final_project.md)|15–20시간|선택 트랙의 작은 데이터 서비스|기준선과 개선 시스템 비교·시연|

과제 1·2는 개인 과제다. 최종 프로젝트는 개인 또는 2–3인 팀으로 수행한다. 마감 시각과
제출 플랫폼은 LMS 공지를 따른다.

## 먼저 알아둘 용어

|용어|쉬운 설명|
|---|---|
|문서(document)|검색하거나 분류하려는 글 한 건|
|질의(query)|사용자가 검색창에 입력하는 질문이나 검색어|
|기준선(baseline)|새 방법이 정말 나은지 비교하기 위한 단순한 방법|
|희소 벡터|대부분 값이 0인 TF–IDF 같은 표현|
|밀집 임베딩|문장 의미를 비교하기 위해 학습된 실수 벡터|
|관련 문서 정답(qrels)|각 질의에 어떤 문서가 정답인지 적은 표|
|개발|방법과 설정을 연습하고 선택하는 데이터|
|최종 평가|설정을 고정한 뒤 마지막에 성능을 확인하는 데이터|
|상위 k개|점수가 높은 결과를 위에서부터 k개 선택한 것|
|오류 분석|틀린 결과를 모아 왜 틀렸는지 구체적으로 설명하는 작업|
|재현성|다른 사람이 같은 코드를 실행해 같은 결과를 얻을 수 있는 성질|

## 모든 과제에 적용하는 작업 순서

### 1단계 · 아주 작은 예제로 실행한다

제공된 [`data/policy_documents.csv`](../data/policy_documents.csv) 또는 직접 만든 문서
5–10개로 코드가 처음부터 끝까지 실행되는지 확인한다. 이 단계에서는 점수가 낮아도 괜찮다.

### 2단계 · 최소 데이터로 확장한다

과제 문서의 최소 개수까지 데이터를 늘린다. ID 중복, 빈 본문, 잘못된 인코딩을 먼저
검사한다.

### 3단계 · 기준선을 완성한다

TF–IDF처럼 간단한 방법을 먼저 실행한다. 기준선이 동작해야 임베딩 방법이 실제로 무엇을
개선했는지 알 수 있다.

### 4단계 · 임베딩 방법을 같은 조건에서 비교한다

문서와 질의, 평가 지표는 그대로 두고 표현 방법만 바꾼다. 최종 평가 결과를 본 뒤 유리한 설정을
계속 고르면 공정한 비교가 아니다.

### 5단계 · 틀린 결과를 설명한다

평균 점수만 제출하지 않는다. 실제 질의, 예상 문서, 검색된 문서와 점수를 나란히 놓고
토큰화, 동의어, 숫자, 날짜, 부정 표현 등 구체적인 원인을 찾는다.

## 공통 실행 규칙

- Python 3.10 이상 또는 Google Colab을 사용한다.
- Notebook 첫 셀에서 `SEED = 42`를 설정한다.
- 개인 컴퓨터의 절대경로 대신 상대경로를 사용한다.
- 모델 이름, 주요 라이브러리 버전과 실행일을 기록한다.
- Notebook은 **런타임 다시 시작 → 전체 셀 실행**으로 오류 없이 끝나야 한다.
- API 키, 개인정보와 비공개 데이터는 Notebook이나 GitHub에 올리지 않는다.
- 유료 API가 없어도 기준선과 평가 부분은 실행되어야 한다.

## 공통 데이터 형식

`documents.csv`의 최소 열은 다음과 같다.

```csv
doc_id,title,text,source,license
D001,청년 창업 지원,만 39세 이하 예비창업자를 지원한다.,공공기관 URL,공공누리
```

`queries.csv`의 최소 열은 다음과 같다.

```csv
query_id,query_text,split
Q01,청년이 받을 수 있는 창업 지원은?,dev
```

`qrels.csv`의 최소 열은 다음과 같다.

```csv
query_id,doc_id,relevance
Q01,D001,1
```

초급 과제에서는 `relevance=1`이면 관련 문서, `0`이면 관련 없는 문서로 사용한다.

교수자가 링크를 열 수 있도록 공유 권한을 확인한다.

## 생성형 AI 사용

생성형 AI를 코드 설명, 디버깅, 문장 교정에 사용할 수 있다. 사용 자체는 감점하지 않는다.
그러나 다음은 반드시 지킨다.

1. AI가 만든 코드를 직접 실행한다.
2. 입력을 바꾸어도 동작하는지 확인한다.
3. 틀린 제안이나 수정한 부분을 [AI 사용 기록](templates/AI_USAGE.md)에 남긴다.
4. 구술 확인에서 코드와 결과를 자신의 말로 설명한다.

설명할 수 없는 AI 생성 코드는 해당 구현 점수를 받을 수 없다.
