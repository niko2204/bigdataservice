# 과제 2 · 문서를 나누고 근거가 있는 답변 만들기

> 문서에서 관련 부분을 찾고, 찾은 근거만 사용해 답한다. 근거가 없으면 응답을 보류한다.

|항목|내용|
|---|---|
|수행 형태|개인|
|교과목 반영|10%|
|권장 시간|7–9시간|
|연결 수업|7주차 검색 평가, 8주차 벡터 검색과 RAG|
|최소 범위|원문 10개, 질문 12개, 청크 크기 2개, 검색기 2개|
|제출|Notebook, CSV 7개, PDF 3쪽, AI 사용 기록|

공통 실행·제출 규칙은 [과제 안내](README.md)를 먼저 읽는다.

## 1. RAG를 쉽게 이해하기

RAG는 크게 두 단계다.

1. **검색(retrieval)**: 질문과 관련된 문서 조각을 찾는다.
2. **답변(answering)**: 찾은 조각만 이용해 답한다.

예를 들어 질문이 `장학금 신청은 언제까지인가요?`라면 시스템은 다음처럼 동작해야 한다.

```text
질문
  ↓
관련 청크 검색: [D03-C02] 신청 기간은 8월 28일까지이다.
  ↓
답변: 신청 기간은 8월 28일까지입니다. [D03-C02]
```

관련 내용이 문서에 없다면 다음처럼 답한다.

```text
제공된 문서로 확인할 수 없습니다.
```

이번 과제는 LLM의 멋진 문장을 평가하지 않는다. **정답 근거를 찾았는지, 답변이 근거와
일치하는지, 근거가 없을 때 멈추는지**를 평가한다.

## 4. 1단계 · 원문 준비 — 10점

### 4.1 데이터 범위

다음 조건을 만족하는 원문 **10개 이상**을 준비한다.

- 문서마다 두 문단 이상의 내용이 있는 것이 좋다.
- 전체 문서를 나누었을 때 청크가 50개 이상 생성되어야 한다.
- 출처와 이용 근거를 기록한다.
- 개인정보와 비공개 자료를 사용하지 않는다.

과제 1의 데이터를 사용할 수 있지만, 문장이 너무 짧아 나눌 필요가 없다면 더 긴 문서를
추가한다.

`documents.csv` 예시:

```csv
doc_id,title,text,source,license
D01,청년 창업 지원,"지원 대상은 만 39세 이하이다. 신청 기간은 8월 1일부터 28일까지이다.",URL,공공누리
```

### 4.2 먼저 2개 문서로 연습

처음부터 10개 전체를 사용하지 않는다. 문서 2개를 읽고 문단 또는 문장 경계가 어떻게
나뉘는지 직접 확인한 다음 전체 데이터로 확장한다.

## 5. 2단계 · 질문과 정답 근거 만들기 — 20점

### 5.1 질문 12개

다음과 같이 만든다.

|분할|답변 가능|답변 불가|합계|
|---|---:|---:|---:|
|개발|3개|1개|4개|
|최종 평가|5개|3개|8개|
|합계|8개|4개|12개|

**답변 가능**은 문서에서 답을 찾을 수 있는 질문이다.

**답변 불가**는 주제는 비슷하지만 제공 문서에는 답이 없는 질문이다.

`questions.csv` 예시:

```csv
question_id,question,split,answerable
Q01,청년 창업 지원의 나이 조건은?,dev,1
Q02,지원금은 매월 언제 입금되나요?,test,0
```

### 5.2 정답과 근거

`gold_answers.csv`를 작성한다.

```csv
question_id,gold_answer,gold_doc_id,evidence_text
Q01,만 39세 이하,D01,지원 대상은 만 39세 이하이다.
Q02,제공 문서로 확인할 수 없음,,
```

- 답을 찾을 수 있으면 짧은 정답, 원문 ID와 근거 문장을 적는다. 초급 평가에서는 질문마다
  가장 중요한 원문 하나를 `gold_doc_id`로 사용한다.
- 답을 찾을 수 없으면 `gold_doc_id`와 `evidence_text`를 비운다.
- 최종 평가 정답은 시스템 결과를 보기 전에 작성한다.

> **왜 답이 없는 질문도 필요한가?** 실제 서비스에는 문서에 없는 질문도 들어온다. 시스템이
> 근거 없이 그럴듯한 답을 만드는지 확인하려면 답변 불가 질문이 필요하다.

## 6. 3단계 · 문서를 두 가지 크기로 나누기 — 15점

### 6.1 청크란?

긴 문서 전체를 한 번에 검색하면 중요한 한 문장이 약해질 수 있다. 그래서 문서를 작은
조각인 **문서 조각(청크)**로 나눈다.

이번 과제에서는 문자 수 기준으로 다음 두 조건만 비교한다.

|조건|청크 크기|겹침률|
|---|---:|---:|
|작은 청크(`small`)|200자|0자|
|큰 청크(`large`)|500자|0자|

문서 특성상 값이 부적절하면 개발 결과를 보기 전에 이유를 적고 바꿀 수 있다. 겹침률 비교는
필수가 아니며 선택 확장 활동으로 둔다.

### 6.2 청크 형식

```csv
chunk_id,doc_id,chunk_order,text
D01-C00,D01,0,지원 대상은 만 39세 이하이다.
D01-C01,D01,1,신청 기간은 8월 1일부터 28일까지이다.
```

필수 확인:

- 모든 청크에 원문 `doc_id`가 있다.
- `chunk_id`는 중복되지 않는다.
- 빈 청크가 없다.
- 원문의 마지막 내용이 사라지지 않는다.
- 같은 입력과 크기로 다시 실행하면 같은 `chunk_id`가 만들어진다.

시작 함수:

```python
def chunk_text(text, chunk_size):
    chunks = []
    for start in range(0, len(text), chunk_size):
        chunk = text[start:start + chunk_size].strip()
        if chunk:
            chunks.append(chunk)
    return chunks
```

문장 중간이 잘리는 문제를 발견했다면 설명하고 문장 단위 분할로 개선해도 된다. 하지만
복잡한 청크 라이브러리를 새로 구현할 필요는 없다.

## 7. 4단계 · 검색기 만들기 — 20점

### 7.1 먼저 TF–IDF로 청크 크기 비교

과제 1의 TF–IDF 검색 코드를 청크에 적용한다.

1. 작은 청크로 검색한다.
2. 큰 청크로 검색한다.
3. 개발 질문 4개에서 `Recall@3`과 `MRR`을 비교한다.
4. 더 적절한 청크 크기 하나를 선택한다.

정답은 `gold_doc_id` 기준으로 판단한다. 검색된 청크의 `doc_id`가 정답 문서와 같으면 관련
검색으로 본다.

### 7.2 선택한 청크에서 밀집 임베딩 검색 추가

선택한 청크 크기에서 과제 1의 문장 임베딩 검색기를 적용한다.

- 필수 비교: TF–IDF vs 밀집
- 반환 결과: `rank`, `chunk_id`, `doc_id`, `score`, `text`
- 반환 개수: 상위 3개

```python
def retrieve(query, system="tfidf", k=3):
    # TODO: 점수가 높은 청크 k개를 반환한다.
    pass
```

### 7.3 두 지표

#### 재현율@3

정답 문서가 상위 3개 검색 결과 안에 있는 질문의 비율을 확인한다.

#### MRR

첫 정답이 1위면 1, 2위면 1/2, 3위면 1/3이다. 정답이 상위 3개에 없으면 0이다.

개발에서 방법을 선택한 뒤 최종 평가를 평가한다. 최종 평가 결과를 보고 청크 크기나 모델을 다시 고르지
않는다.

## 8. 5단계 · 답변하고 인용하기 — 15점

### 8.1 필수 동작

검색된 청크에 답이 있으면 짧게 답하고 `[chunk_id]`를 붙인다.

```text
신청 기간은 8월 28일까지입니다. [D03-C02]
```

근거가 없으면 다음 문장을 반환한다.

```text
제공된 문서로 확인할 수 없습니다.
```

### 8.2 구현 방법 선택

다음 중 하나를 선택한다. 어느 방법을 사용해도 같은 배점을 적용한다.

1. **추출형**: 검색된 청크에서 정답 문장을 사람이 선택하거나 간단한 규칙으로 추출
2. **템플릿형**: 정해진 형식에 검색된 근거 문장을 넣어 답변
3. **LLM 사용**: 검색된 청크만 prompt에 넣고 답변과 인용 생성

초보자에게는 1번이나 2번을 권장한다. LLM API는 필수가 아니며 유료 모델을 써도 가산점이
없다.

### 8.3 단순 응답 보류 규칙

다음 중 하나를 선택해 코드에 적는다.

- 1위 검색 점수가 개발 데이터에서 정한 값보다 낮으면 응답 보류
- 상위 3개 청크를 읽었을 때 답을 지지하는 근거가 없으면 응답 보류
- LLM이 인용할 청크를 선택하지 못하면 응답 보류

최종 평가를 보기 전에 규칙과 값을 적는다.

## 9. 6단계 · 최종 평가와 오류 6건 — 15점

### 9.1 최종 평가 질문 8개 평가

다음 세 가지를 계산한다.

1. TF–IDF 검색의 재현율@3과 MRR
2. 밀집 임베딩 검색의 재현율@3과 MRR
3. 올바르게 답하거나 응답을 보류한 질문의 비율

각 답변은 사람이 읽고 다음처럼 표시한다.

- `1`: 핵심 답과 인용 근거가 맞음
- `0`: 답이 틀리거나 근거가 답을 지지하지 않음

`metrics.csv` 예시:

```csv
system,split,recall_at_3,mrr,answer_behavior_accuracy
tfidf,test,0.63,0.54,0.63
dense,test,0.75,0.68,0.75
```

### 9.2 오류 분석 6건

다음에서 2건씩 고른다.

- **검색 오류 2건**: 정답 문서가 상위 3개에 없음
- **답변/인용 오류 2건**: 정답 청크는 찾았지만 답이나 인용이 틀림
- **응답 보류 오류 2건**: 답할 수 있는데 응답을 보류하거나, 근거 없이 답함

`error_analysis.csv` 예시:

```csv
question_id,failure_stage,expected,observed,reason,possible_fix
Q05,retrieval,D07,D03,질의와 문서의 표현이 다름,hybrid 검색 고려
```

개선 방법은 제안만 하면 되며 다시 구현할 필요는 없다.
