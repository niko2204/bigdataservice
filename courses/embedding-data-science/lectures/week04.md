# 04주차 · 문맥 임베딩과 Transformer

        - 원본 연계: 2장 Contextualized Word Embeddings + 3장 Looking Inside LLMs
        - 권장 수업: 개념 45분 · 수학 25분 · 시연 20분 · 실습 70분 · 토론/정리 20분
        - 실습 파일: `../notebooks/week04.ipynb`

        ## 학습목표

        - 동일한 단어가 문장마다 다른 벡터를 가져야 하는 이유는 무엇인가?
- Self-Attention이 문맥을 결합하는 과정은 무엇인가?
- 토큰 임베딩과 문장 임베딩은 어떻게 다른가?

        ## 핵심 개념

        이번 주의 핵심은 **문맥 임베딩과 Transformer**을 단순한 라이브러리 사용법이 아니라
        데이터 표현, 학습 가정, 평가 방법의 연결로 이해하는 것이다. 임베딩은 원시 데이터를
        유한 차원의 벡터로 바꾸는 함수이며, 좋은 임베딩의 기준은 응용 문제에 따라 달라진다.
        검색에서는 관련 항목의 순위를, 분류에서는 결정 경계를, 군집에서는 구조적 분리를
        보존해야 한다. 따라서 한두 개의 유사도 예시만으로 모델의 우수성을 결론 내려서는 안 된다.

        ## 수학적 초점

        Scaled dot-product attention, Softmax, 위치 정보

        수식은 계산 자체보다 각 기호가 데이터와 어떤 관계를 나타내는지 설명하는 데 사용한다.
        학생은 작은 예제를 손으로 계산한 뒤 Notebook 출력과 비교하고, 값이 달라진 경우
        토큰화·정규화·모델 설정 중 무엇이 원인인지 찾아야 한다.

        ## 교수 시연

        작은 행렬로 Attention을 계산하고 선택적으로 한국어 BERT 토큰 임베딩을 비교한다.

        시연 전 학생에게 결과를 먼저 예측하게 하고, 실행 후 예상과 다른 결과를 중심으로 토론한다.
        모델 이름이나 점수만 제시하지 말고 입력, 벡터 차원, 유사도 정의, 평가 데이터와 오류 사례를
        함께 화면에 표시한다.

        ## 수업 중 질문

        1. 현재 벡터에서 가까움은 무엇을 의미하는가?
        2. 이 결과가 데이터의 속성인가, 모델이 학습한 속성인가?
        3. 다른 거리 함수나 기준선을 사용하면 결론이 바뀌는가?
        4. 실제 서비스에서 가장 위험한 오류는 무엇인가?

        ## 학생 활동

        - 코드 실행 전에 결과에 대한 가설을 두 문장으로 작성한다.
        - 제공된 예제 데이터 세 개 이상을 자신이 수집한 한국어 데이터로 교체한다.
        - 성공 사례와 실패 사례를 각각 하나 이상 분석한다.
        - 생성형 AI를 사용한 경우 프롬프트와 검증 과정을 Notebook 끝에 기록한다.

        ## 형성평가

        - 개념 설명 2점
        - 수치 또는 그래프 근거 2점
        - 오류 사례 분석 2점
        - 코드 재현성 2점
        - 자신의 언어로 작성한 결론 2점

        ## 교수자 유의사항

        학생이 사전학습 모델의 결과를 정답처럼 받아들이지 않도록 한다. 모델 다운로드 실패,
        GPU 부족 또는 API 키 부재 상황에서도 TF-IDF나 작은 행렬 예제로 핵심 원리를 학습할 수 있게
        기준선 코드를 먼저 실행한다. 최신 모델 사용은 선택 확장 실습으로 두고, 평가 설계와 해석을
        필수 평가 대상으로 삼는다.
